Task completion — “Log a result?” with evidence upload

No task-level KRs. When you complete a task that produced a measurable output, an optional prompt creates a Record linked to that task. Minimal by default — Value + Unit; everything else behind ⋯ more. Evidence files upload against the record and stay previewable + downloadable afterwards. Dismiss the prompt → nothing created.

Milestone — auto-achieve from tasks or a KR

Project-level milestones already exist. New: a milestone can auto-flip to achieved when its linked tasks complete (all / any, per milestone) or when a linked Key Result crosses a threshold. Manual override always wins; reopening a task doesn't un-achieve.

Progressive-disclosure rules

Every new GoalsHQ screen reuses patterns already in the codebase and keeps the default view minimal.

  • An entity with metrics not enabled looks exactly like today — zero new UI.
  • Enabling a capability reveals the minimum control — one KR field, one record row — never a panel of inputs.
  • Extra detail is always one more click — a chevron, a ⋯ more, an icon toggle.
  • Strategy modal = ProjectModal pattern: expandedSections + dot-badge icon row.
  • Evidence upload / preview / download = the existing task-attachment stack, generalised.
  • Colour = Shared/ColorPicker; project/goal pickers = the AreaModal checkbox dropdown.
  • Report AI narrative is fetched only when its card is opened — never on page load.
Reused as-is: ProjectModal.tsx · TaskAttachmentsSection.tsx · AttachmentPreview.tsx · attachmentsService.ts · ColorPicker.tsx · AreaModal.tsx checkbox dropdown · ReportsPage.tsx SVG charts.
